## 1. What this is, in one paragraph

The user asked for a presentation-grade, multi-page visual atlas of the pragma knowledge graph: the RDF graph that the `pragma` CLI from `canonical/pragma-core` embeds, about 65k triples. The site has 16 pages. They range from schema, tier, anatomy, token and coverage views to whole-graph 2D/3D maps. The two pages the user cares about most right now are the **Board** and the **Compositions** page. Both render the *real* published pragma React components (server-rendered, styled by the real pragma CSS inside Shadow DOM islands) on a packed grid of frames with 3D depth driven by HTML nesting depth. The work is live as a private claude.ai artifact. This folder holds every source file and script needed to rebuild and keep developing it.

### 6.2 CSS: one flattened bundle, rewritten for Shadow DOM

- **`entry.css`** imports the styles package, the global package's `index.css`, the form package's `dist/esm/index.css`, then every form component sheet explicitly, deepest first, then all 19 app-package sheets listed in `appcss.txt`.
- **`flatten.ts`** inlines every `@import` into `bundle.css` and hoists the `@layer normalize, ds.tokens, ...` order statement to the top. It must only rewrite imports outside comments. An earlier version corrupted a comment and dropped the layer statement and the normalize layer. That produced Arial buttons and wrong spacing.
- **`island.py`** turns `pragma.css` into `pragma-island.css` for Shadow DOM:
  - It strips comments but keeps normalize's MIT licence notice.
  - It rewrites `:where(:root)` and `:root` to `:host`.
  - It rewrites `:root:not(.light)` to `.island:not(.light)`. This rewrite matters: it keeps a forced Light theme from inheriting dark hover deltas on a dark device.
  - It rewrites `html, body, #storybook-root` and standalone `html` and `body` to `.island`.
  - It appends `extra-logo.css`, the story-only `.ds.canonical-logo` rule, under `@layer ds.components.apps`.

Rebuild sequence:

```bash
cd $WORK/render && bun run flatten.ts && cp bundle.css /home/user/graph-atlas/pragma.css && python3 island.py
```

Why a hand-built bundle: without a bundler, nothing collects the per-component `import "./styles.css"`. The form package's `index.css` holds only tokens and density, not its 29 component sheets. Section 12 explains the idiomatic route in a real app.

### 6.3 Islands, in `atlas.js`

`island(host, html, {context, scheme, layer, screen})` attaches a shadow root containing:

```html
<style>@layer helpers;</style>
<link rel="stylesheet" href="pragma-island.css">
<style>${ISLAND_CSS}</style>
<div class="island comfortable app [light|dark]" data-layer="elements|components|">
  <div class="surface [screen]" style="--screen:NNNpx">…component html…</div>
</div>
```

It returns a promise that resolves when the stylesheet loads, so measure only after that. `islandSet(sr, {context, scheme, layer, dz2})` updates an island in place. `depthOf(sr)` returns the maximum element nesting depth under `.surface`.

Why Shadow DOM and not iframes:

- Iframes flatten 3D transforms.
- A page-level `pragma.css` would restyle the atlas pages.

The `.island` element carries the Storybook root classes, `comfortable app`, so density and context tokens resolve as they do in Storybook. Geometry parity with Storybook was verified for button, label, tabs, breadcrumbs, input and select. Only container widths differ.

`ISLAND_CSS` contains:

- **Helper classes in `@layer helpers`.** These are `.stack-v`, `.titlebar`, `.actions`, `.row`, `.tiles-3`, `.cards-2`, `.big`, `.h2`, `.muted`, `.small`, `dl.keys`, `.brand-mark` and the `.screen-*` classes. Compositions use them for layout glue only.
- **`.surface.screen` rules.** These use `contain: layout` so `position: fixed` dialogs get the frame as their containing block. The rules then position `dialog[open].ds.modal` centred and `dialog[open].ds.side-panel` docked to the right.
- **Elevation rules.** See the next section.

### 6.4 Elevation, the 3D effect

There are two levels of elevation.

1. **The whole frame rises.** It is lifted by `--lift: 45px * k * depth / maxDepthAcrossFrames`, using `transform: translateZ(...)`. Here `k` is the Depth select value: 1 subtle, 2 medium (the default), 3.5 strong. The lift is normalised so frames don't magnify into each other through perspective.
2. **Every element inside an island rises.** Under layering, each element rises one constant step per nesting level, `translate: 0 0 var(--dz2)` on `.surface *`. The rules set `transform-style: preserve-3d` on every element in the surface. Height is therefore linear in HTML depth from the component root.

Elevation uses the individual `translate` property, never `transform`. Pragma never uses `translate`, so the lift composes with pragma's own transforms. An earlier cumulative-transform version compounded the offsets and misaligned focus rings.

Layer modes:

- `elements` lifts every element.
- `components` lifts only `.ds` elements.
- An empty value turns layering off.

Open dialogs and the scrim are lifted extra, 6× and 5× `--dz2`, so overlays stay above deep backdrop content.

The stage:

- **Tilted.** A `.stage.tilted` wrapper applies `perspective`, and the board gets `rotateX(9deg) rotateY(-3deg)`. Pointer movement nudges both angles.
- **Pivot.** `pivot()` keeps the perspective origin at the viewport centre while scrolling.
- **Flat.** The flat mode sets `perspective: none`.
- **Exploded.** The `Exploded` toolbar button (or the `x` key, ignored while typing in an island input) adds `.exploded` to the stage: a teardown view. It switches Layer to `components` (and restores the previous pick on the way out), because lifting every element carries a button's label away from its background, white on white; by component, a card floats above the frame and its buttons above the card. The step is `18px × k`, where `k` is the Distance slider (0.5…5, default 2, so 36px per component level), instead of `1.5px × k`; the frames' `--lift` is pinned to 0 so they are the flat base; the board sits behind a 3600px perspective pulled back 200px, so depth reads as displacement rather than scale, with the pivot at 38% of the viewport rather than 50%. Turning it on turns the tilt on; turning the tilt off turns it off. The packer runs with `gap: 56` instead of 32 while exploded, so the chassis rows have air under the stacks that climb over them (near layers sort in front within the board's one `preserve-3d` context).

  **Orbit.** Exploded, the pointer orbits the board instead of nudging it: its place across the stage gives `--ry` −50°…50°, its place down the viewport gives `--rx` 15° (looking down) …80° (looking along); the board's transition drops to .35s so the follow glides. A drag with a held mouse button or a finger pins the view as it starts and turns it from there like a trackball: dragging down brings the eye up over the board, to straight down at 0°; dragging up lowers it, to nearly edge-on at 88°; the view holds after the drag until it is unpinned. (The hover maps the other way, pointer down the screen = looking along; the user found the trackball direction right for a drag and the hover direction right for a hover.) `touch-action: pan-y`, so a vertical drag still scrolls a phone and a finger only turns `--ry`; `pointerdown` suppresses the default so no text is selected; the click that ends a drag is ignored via a short-lived `data-dragged` flag; a drag that starts on a control inside an island is left alone. `Control` (or the `Pin view` button, shown only while exploded) pins the view by hand: hover is ignored, drags still turn it, the arrow keys turn it 4° (12° with Shift) within the drag ranges, and `Escape` unpins so the pointer orbits again. Leaving Exploded clears the pin and the inline angles. Under `prefers-reduced-motion` the hover follow is off; drag and keys still work.

  **Shadow cue.** Motion alone was not enough in a still frame, so a component that paints something of its own (computed `background-color` with alpha or a border, marked `data-solid` by `island()` once pragma's styles apply, along with `--lvl`, its count of `.ds` ancestors) casts a light shadow whose offset and blur grow with its height: `0 (lvl × step × .18) (lvl × step × .55) rgba(0,0,0,.14)`, `.5` alpha in dark. Transparent wrappers get nothing, so they never turn into boxes. The rule is gated on `.island.exploded`, which `islandSet(sr, { exploded })` toggles.

Two things flattened the islands' 3D before this view existed, unnoticed at a 3px step:

- **The island root was flat.** `preserve-3d` was set on `.surface` and everything below it, but not on `.island` between the host and the surface. One flat element flattens its whole subtree into its plane, so the per-element lifts projected at a fraction of their size in Chromium and may not have shown at all in other engines. `.island[data-layer]` now preserves 3D too.
- **Pragma's overflow.** `.ds.card`, `.ds.tile`, `.ds.accordion`, `.ds.modal`, `.ds.modal-content` and the side navigation's `.ds.content` have `overflow: hidden` or `auto`. Any overflow other than `visible` or `clip` groups the element's 3D descendants into one plane. `ISLAND_CSS` sets them to `overflow: visible` under `.island[data-layer]`; their radius resolves to 0 and none has content to scroll, so nothing visible changes. (`clip` would also do in Chromium, but `visible` is the safe value across engines.)

### 6.5 Packing: `packBoard` in `atlas.js`

`packBoard(board, frames, {minCol, gap, lookahead})` is a skyline packer. Frames are absolutely positioned.

1. **Columns.** The column count is `floor((width + gap) / (minCol + gap))`.
2. **Spans.** Each frame declares `data-span`, its preferred span, plus `data-min` and `data-max`. Heights are measured per span with `offsetHeight` and cached.
3. **Filling.** The packer always fills the lowest skyline segment. Among the next few frames it picks the best one by this score:

   ```
   |k - pref| * 3 + queueIndex * 2 + (leaves an unusable sliver ? 4 : 0)
   ```

   If nothing fits, the segment is raised to its lower neighbour.

4. **Widening.** Frames grow sideways into empty columns over their vertical range.
5. **Stretching.** Frames extend down to the next frame below, or to the board bottom. The result is 100% coverage with no gaps.

Settings per page:

- **Compositions** uses `minCol 170, gap 32`. Minimum spans are 4 for app-shell and side-panel, 3 for modal, page-header, status-tiles and release-cards, and 2 otherwise. `data-max` is `size + 1`.
- **Board** uses `minCol 230, gap 24` with `data-min = size`, and frames use `overflow: hidden`.

Both pages re-pack when the width changes and after fonts load. The packer runs with the tilt temporarily removed, so measurements are untransformed.

Verified: 100% coverage and no overlaps at 400, 1280 and 1600 px wide, light and dark.

### 6.6 Theme and context controls

The boards have a Theme select: follow page, light or dark.

- **`syncTheme`** puts `.light` or `.dark` on `<html>`. `atlas.css` has `:root.light` and `:root.dark` rules that set `color-scheme`. Without them, a forced Light theme on a dark device painted dark text on a dark page. That was the bug fixed in version 11.
- **Islands** get the same scheme class via `islandSet`.
- **"Follow page"** follows claude.ai's `data-theme` attribute when present, then the device setting.

The Context select switches islands between `app`, `site` and `docs`. The board then re-packs.

### 6.7 Clicks and details

Clicking a frame opens the atlas side panel, `showPanel`. On Compositions it lists the blocks in "Made of", the curies and pragma CLI commands. The click handler uses `e.composedPath()[0]` and ignores clicks on interactive elements inside the island.

### 6.8 Fonts

Ubuntu Sans comes from `site/fonts/`, copied from `@canonical/ds-assets`. It is declared with `@font-face` on the document, so the islands inherit it.

Ubuntu Sans Mono comes from Google Fonts. The mono files in `ds-assets` are actually HTML error pages; this is tracked upstream as PRA-146. Without a working mono face, the pragma mono stack falls through to "Noto Color Emoji" before the monospace fallbacks, which spaces digits oddly.

## 11. Decisions and lessons (bugs already fixed; don't reintroduce them)

| Symptom | Cause | Fix |
|---|---|---|
| Arial buttons, wrong spacing | Flattener rewrote an `@import` inside a comment; layer statement and normalize lost | Rewrite only non-comment segments |
| Native input borders, broken field spacing | Form `index.css` doesn't include component sheets | Import all form sheets in `entry.css` |
| Invalid hook call | Nested React copies under `@canonical/*/node_modules` | Delete them; pin React 19.3.1 |
| Focus rings misaligned in 3D | Cumulative per-depth transforms | One constant `translate` step per level |
| Tokens missing in islands | `:root`, `html` and `body` don't match inside a shadow root | Selector rewrites in `island.py` plus root classes on `.island` |
| Atlas pages restyled | Page-level `pragma.css` link | Removed; islands only |
| Odd digit spacing | Mono font files are HTML (PRA-146); stack falls to emoji | No mono `@font-face`; Google Fonts mono |
| Dialogs under the backdrop | Deep backdrop elements had a higher Z than the shallow dialog | Lift `dialog[open]` and the scrim |
| Frames overlapping visually | Perspective magnification of large lifts | Normalised `--lift`, wider gaps, `perspective: none` when flat |
| App shell overflow | Screen too short | Screen raised to 720 px |
| Side navigation title overlapped | Custom orange square brand | Replaced by pragma's `CanonicalLogo` replica |
| Every frame full width | Packer overweighted exact fit | Score preferred span first |
| Badge stretched full width | Flex or grid stretch in a composition | Intrinsic width |
| Light theme broken on dark devices | Theme select set a class; page `color-scheme` listened only to `data-theme` | `:root.light` and `:root.dark` in `atlas.css`; `.island:not(.light)` rewrite |
| Islands nearly flat under layering | `.island` root had `transform-style: flat`; pragma's `overflow: hidden` on cards, tiles, accordions, modals groups 3D descendants | `preserve-3d` on `.island[data-layer]`; `overflow: visible` for those in `ISLAND_CSS` |
| Exploded view: primary buttons became bars, labels invisible | Lifting every element carried white labels off their dark backgrounds | Exploded layers by component (`.ds`), not by element |

### 12.3 Answer: how to load component CSS idiomatically

1. Import `@canonical/styles`, optionally preceded by `@canonical/styles/fonts`, first in the app entry. It sets the layer order.
2. Import components by name. Each component module imports its own `styles.css`, and the bundler collects them.
3. Also import `@canonical/react-ds-global-form/dist/esm/index.css` when using forms. No component imports it.
4. Optionally import `@canonical/react-ds-global/index.css`. This aggregate makes all global component CSS present at first paint for lazy routes.
5. Put `class="app comfortable"` on `<body>` or `<html>`.
6. Put app CSS in `@layer app`.

Things to avoid:

- A `layer(...)` keyword on pragma imports.
- `!important`.
- Relying on bundle order.

Gaps:

- Only the global package has a component aggregate. The form and app packages have none, and the app package has no `exports` map.
- Readmes disagree on `ds.components.app` vs `ds.components.apps`, and on whether app-tier sheets are wrapped yet. In fact they are wrapped.

## 14. Gotchas checklist

- **Measure islands only after their promise resolves.** Before the stylesheet loads, heights are wrong and packing breaks.
- **Re-pack after anything that changes frame heights.** That includes fonts, context, theme if it affects metrics, and resize.
- **Don't add `transform` to elements inside islands for elevation.** Use `translate` only.
- **Don't add a page-level `pragma.css`.**
- **Keep `island.py`'s `:root:not(.light)` rewrite as `.island:not(.light)`.**
- **When regenerating `pragma-island.css`, confirm the logo rule survived:** `grep -c canonical-logo pragma-island.css` should print 1.
- **The artifact sandbox blocks external images.** Use data URIs.
- **The claude.ai host sets `data-theme` on `<html>`.** The pages respect it unless the Theme select forces a scheme.
- **This container is temporary.** Commit and push anything worth keeping to the working branch.
