# The Wrapper Pattern

Built-in `Field` variants compose input binding with field chrome. The standard wrapper supplies labels, descriptions, errors, accessibility properties, optional marking, conditional display and middleware; the binding connects the input to react-hook-form. Checkbox and switch use inline toggle chrome, while hidden fields use an invisible wrapper.

These wrappers, `withWrapper`, and `useFieldWrapper` are internal implementation details, not package-root exports. Use `Field` for the built-in wrapped controls. Standalone inputs such as `TextInput` and `SelectInput` are also exported from the package root: they are presentational and need a label and any form binding supplied by the caller.

For standard and toggle wrappers, the wrapper treats a field as required unless `isOptional` is set, and merges explicit `registerProps` over its generated rule. The hidden field's invisible wrapper does not pass `isOptional` to that rule: its generated registration is required unless overridden with `registerProps`. Native-bound controls register with react-hook-form; use the form's `defaultValues` for initial form state. A native `defaultValue` is a separate input prop, not a replacement for the form default. Native `value` controls the displayed input, while the registered `onChange` handler belongs to react-hook-form; use form methods or a custom controlled component when coordinating state.

`inputType="custom"` renders the supplied component directly and does not apply the built-in wrapper or binding. See **Creating Custom Fields** for an example using public APIs.
