# Creating Custom Fields

`Field` renders a custom component directly, passing its props except `inputType` and `CustomComponent`; React also consumes `key`. It does not add form binding, labels, errors, conditional display, middleware, or unmount handling to a custom component. Implement the capabilities your field needs. `withWrapper` and its wrapper hooks are internal and are not package exports.

For example, this component registers a custom input using the `Form` provider and supplies its own label and validation message:

```tsx
import { Field, Form, type InputProps } from "@canonical/react-ds-global-form";
import { useFormContext } from "react-hook-form";

type CodeProps = InputProps<{ label: string; maxCharacters: number }>;

function CodeField({ name, label, maxCharacters, registerProps }: CodeProps) {
  const { register, getFieldState, formState } = useFormContext();
  const { error } = getFieldState(name, formState);
  const errorId = `${name}-error`;
  return (
    <div>
      <label htmlFor={name}>{label}</label>
      <input
        id={name}
        maxLength={maxCharacters}
        aria-invalid={!!error}
        aria-describedby={error ? errorId : undefined}
        {...register(name, registerProps)}
      />
      {error && <p id={errorId} role="alert">{error.message}</p>}
    </div>
  );
}

function Example() {
  return (
    <Form onSubmit={(values) => console.log(values)}>
      <Field inputType="custom" CustomComponent={CodeField} name="code"
        label="Code" maxCharacters={8} registerProps={{ required: "Enter a code" }} />
      <button type="submit">Submit</button>
    </Form>
  );
}
```

The component's props are inferred in JSX: required custom props and their types are checked. `inputType`, `CustomComponent`, and React's `key` are reserved and cannot be custom component props. For a typed field map, supply the custom component's props to `FieldProps`:

```tsx
import type { FieldProps } from "@canonical/react-ds-global-form";

const fields = [
  { inputType: "text", name: "title", label: "Title" },
  { inputType: "custom", CustomComponent: CodeField, name: "code", label: "Code", maxCharacters: 8 },
] satisfies FieldProps<CodeProps>[];

fields.map((field) => <Field key={field.name} {...field} />);
```

For a map with different custom components, use a separate discriminant to preserve each component/props pair. For example, alongside `CodeField` above:

```tsx
type PrefixProps = InputProps<{ label: string; prefix: string }>;

function PrefixField({ name, label, prefix }: PrefixProps) {
  const { register } = useFormContext();
  return (
    <label>
      {label}
      <input placeholder={prefix} {...register(name)} />
    </label>
  );
}

type Definition =
  | { kind: "builtin"; field: Exclude<FieldProps, { inputType: "custom" }> }
  | { kind: "code"; field: Extract<FieldProps<CodeProps>, { inputType: "custom" }> }
  | { kind: "prefix"; field: Extract<FieldProps<PrefixProps>, { inputType: "custom" }> };

const definitions: Definition[] = [
  { kind: "builtin", field: { inputType: "text", name: "title", label: "Title" } },
  { kind: "code", field: { inputType: "custom", CustomComponent: CodeField, name: "code", label: "Code", maxCharacters: 8 } },
  { kind: "prefix", field: { inputType: "custom", CustomComponent: PrefixField, name: "prefix", label: "Prefix", prefix: "Example" } },
];

function MappedField({ definition }: { definition: Definition }) {
  switch (definition.kind) {
    case "builtin": return <Field {...definition.field} />;
    case "code": return <Field {...definition.field} />;
    case "prefix": return <Field {...definition.field} />;
  }
}

// Render inside a Form:
definitions.map((definition) => <MappedField key={definition.field.name} definition={definition} />);
```

`inputType` alone cannot distinguish different custom variants, and spreading their heterogeneous union into `Field` does not infer a single matching props type. `FieldProps` without a type argument accepts custom components that can be rendered with a `name` string. Field names are strings, not paths inferred from the form's model.

For controlled third-party inputs use react-hook-form's `useController` or `Controller` inside the custom component, supplying its value, change and blur handlers. Forward accessibility attributes to the focusable control and provide suitable labels and error relationships.
